# AutoServise "For Example" — For my Portfolio

**Открыть сайт:** https://timur-alt2008.github.io/AutoServise-For-Example-For-my-Portfolio/

Демо-сайт премиального автосервиса для портфолио. Готовая сборка сайта лежит в папке `docs/` (её показывает GitHub Pages),
исходный код — в `client/` и `server/`.

# EXAMPLE Auto Service + Web Inspiration Analyzer

В проекте две части:

1. **Сайт EXAMPLE Auto Service** — демонстрационный сайт вымышленного автосервиса для портфолио (React + TypeScript + Vite).
   Тёмный премиальный дизайн: главный экран с параллаксом, 10 услуг с подробным окном, «Почему выбирают нас» со счётчиками,
   галерея работ с фильтрами и полноэкранным просмотром, шкала процесса, слайдер отзывов, форма записи, контакты со схемой проезда.
   Все контакты, цены, примеры работ и отзывы — **вымышленные демо-данные**, на сайте они так и подписаны (отзывы помечены «Пример отзыва»).
2. **Web Inspiration Analyzer** — рабочая панель разработчика. Вы даёте адреса сайтов (или включаете поиск по API), она загружает разрешённые страницы,
   показывает, что найдено, и предлагает идеи для вашего сайта. **Сама она код сайта не меняет**: идея становится задачей только после вашего одобрения.

## Быстрый старт на Windows

1. **Установите Node.js** (одноразово). Зайдите на <https://nodejs.org>, скачайте версию **LTS** (нужна **22.18 или новее**) и установите, нажимая «Далее».
   Проверить: откройте «Пуск» → `cmd` → введите `node -v` → должно показать `v22.18.0` или больше.
2. **Распакуйте архив** в любую папку, например `C:\Projects\example-auto-service`.
3. **Дважды щёлкните `start.bat`.** Он сам:
   - проверит Node.js,
   - создаст файл `.env` из `.env.example`,
   - при первом запуске выполнит `npm install` (1–3 минуты, нужен интернет),
   - запустит сайт и сервер анализатора и откроет браузер.

Адреса:

| Что | Адрес |
| --- | --- |
| Сайт | <http://127.0.0.1:5173> |
| Панель анализатора | <http://127.0.0.1:5173/#/analyzer> (или ссылка «Панель разработчика» внизу сайта) |

Остановить: нажмите `Ctrl+C` в чёрном окне (если спросит — `Y`).

### То же самое вручную (в терминале)

```bash
npm install
copy .env.example .env      # в macOS/Linux: cp .env.example .env
npm run dev
```

### Если `start.bat` ругается

| Сообщение / симптом | Что делать |
| --- | --- |
| `Node.js is not installed` | Установите Node.js LTS (шаг 1) и **закройте и откройте** окно заново. |
| `Your Node.js is too old` | Установите свежую LTS с nodejs.org. Нужна версия 22.18 или новее. |
| `npm install failed` | Проверьте интернет/VPN/прокси и запустите `start.bat` снова. |
| Браузер показывает «Не удаётся подключиться» | Подождите 10–20 секунд (идёт запуск) и обновите страницу. Адрес должен быть `http://127.0.0.1:5173`. |
| В панели «Сервер анализатора недоступен» | Панель работает только вместе с сервером: запускайте через `start.bat` или `npm run dev`, а не открывайте `index.html` из папки. |
| `EADDRINUSE` / порт занят | Закройте старое окно запуска или смените `PORT` в `.env` (например, `PORT=8790`) и запустите снова. |

## Как пользоваться анализатором

Откройте панель: <http://127.0.0.1:5173/#/analyzer>. Вкладки слева (на телефоне — кнопка «Разделы»):

1. **Dashboard** — сводка по реальным анализам. Пока вы ничего не запускали, везде нули — это нормально, демонстрационных цифр там нет.
2. **Добавить URL** — вставьте от 1 до 5 адресов сайтов за раз (по одному в строке) и нажмите «Проанализировать».
   Анализатор загрузит несколько страниц каждого сайта (главная и публичные страницы услуг/цен/контактов — в пределах лимита из настроек).
3. **Найти референсы** — автоматический поиск похожих сайтов через поисковый API. **Нужен ключ** (см. ниже). Без ключа вкладка честно пишет «не настроен» и ничего не придумывает.
4. **История анализа** — все запуски, статус каждой страницы, найденные блоки, ошибки (например, «robots.txt запрещает» или «сайт показывает защиту от ботов»).
5. **Найденные идеи** — идеи с итоговой оценкой 0–100 (полезность, соответствие проекту, реализуемость, визуальный эффект) и сложностью внедрения. Можно **одобрить** или **отклонить**.
6. **Одобренные идеи** — здесь появляется **задача** для внедрения. Код сайта при этом **не меняется** — вы (или вы вместе с ИИ-помощником) вносите правки отдельно.
7. **Реализованные улучшения** — идеи, которые вы отметили как сделанные.
8. **Настройки источников** — паузы между запросами, тайм-аут, число страниц на сайт, чёрный список доменов, очистка кэша и состояние ключей.

Статусы идей: **новая → одобрена → реализована**, либо **отклонена**. Любой статус можно вернуть назад.

### Что анализатор делает и чего не делает

- Читает только **публичные** страницы по обычным HTTP-запросам; учитывает `robots.txt` (запрет — страница пропускается).
- Между запросами к одному сайту делает паузу (по умолчанию 2 с), ставит тайм-аут (10 с), кэширует ответы (6 ч) и ограничивает число страниц за запуск. Сканирования «всего интернета» нет.
- **Не обходит** авторизацию, CAPTCHA и защиту от ботов: если сайт отвечает защитной страницей, анализатор записывает «заблокировано» и идёт дальше.
- Не заходит на локальные и внутренние адреса (защита от SSRF), не собирает личные данные и секреты.
- Не копирует чужие тексты, изображения и код: из страницы берутся только факты о структуре и набор функций; идеи — «вдохновение», а не готовое решение.
- Фильтр «реалистичности» (восемь вопросов: подходит ли обычному автосервису, не выдумывает ли данные, не даёт ли ложных обещаний, работает ли на телефоне и т. д.) отсеивает то, что демо-сайт не может честно показать — например, карту с точкой несуществующего адреса. Отсеянные идеи видны отдельно, с причиной.
- Интерактивность, которая появляется только в браузере (JavaScript, всплывающие окна), анализатор не выполняет — такие пункты помечаются **«требует браузерной проверки»**.

## API-ключи (необязательно)

Ключи вписываются **только в файл `.env`** в корне проекта (его создаёт `start.bat`). После изменения `.env` остановите запуск (`Ctrl+C`) и запустите снова.

> **Никогда не публикуйте `.env`** — не загружайте его на GitHub, не отправляйте в чат. Он уже добавлен в `.gitignore`.
> Секретные ключи не попадают в браузер: их использует только сервер. Только переменные с префиксом `VITE_` видны в браузере — в них не должно быть ключей.

### Поиск референсов (режим B) — нужен один из двух вариантов

**Вариант 1. Brave Search API**
1. Зарегистрируйтесь на <https://brave.com/search/api/> и создайте ключ (есть бесплатный тариф с ограничением по числу запросов — условия смотрите на сайте).
2. В `.env`: `BRAVE_API_KEY=ваш_ключ`.

**Вариант 2. Google Programmable Search**
1. На <https://programmablesearchengine.google.com/> создайте поисковик (можно «искать по всему интернету») — получите идентификатор `cx`.
2. На <https://console.cloud.google.com/> включите Custom Search API и создайте ключ.
3. В `.env`: `GOOGLE_CSE_KEY=ключ` и `GOOGLE_CSE_CX=идентификатор`.

После перезапуска во вкладке «Найти референсы» статус сменится на «подключён». Результаты поиска кэшируются на 24 часа, чтобы не тратить лимит.

### ИИ-дополнение анализа (по желанию)

1. Ключ — в консоли Anthropic: <https://console.anthropic.com/> (раздел API keys).
2. В `.env`: `ANTHROPIC_API_KEY=ваш_ключ` (модель меняется через `AI_MODEL`).
3. На странице «Добавить URL» появится галочка «Дополнить анализ с помощью ИИ». ИИ получает только извлечённые факты со страницы и предлагает дополнительные идеи — они помечаются «предложено ИИ». API платный: следите за расходами в консоли.

### Приём заявок с сайта в Telegram (по желанию)

По умолчанию форма записи работает в **демо-режиме**: проверяет поля и честно пишет, что ничего не отправлено. Чтобы заявки реально приходили:

1. В Telegram найдите `@BotFather` → `/newbot` → получите токен.
2. Напишите своему боту любое сообщение, затем узнайте `chat_id` (например, через бота `@userinfobot` или `https://api.telegram.org/bot<токен>/getUpdates`).
3. В `.env`:
   ```
   BOOKING_TELEGRAM_BOT_TOKEN=токен
   BOOKING_TELEGRAM_CHAT_ID=chat_id
   VITE_BOOKING_ENDPOINT=/api/bookings
   ```
4. Перезапустите. Теперь форма отправляет заявку на ваш сервер, а он пересылает её в Telegram. В демо-режиме и при ошибке доставки пользователь видит правду, а не «успешно отправлено».

> Это демо-проект с вымышленным адресом и телефоном. Прежде чем использовать форму для настоящего бизнеса, замените контакты и проверьте доставку.

### Пароль для панели

Если сервер открыт только на вашем компьютере (по умолчанию `HOST=127.0.0.1`), пароль не нужен. Если вы публикуете панель в сеть — задайте `ADMIN_TOKEN=длинный_пароль`; без него сервер не стартует на внешнем адресе.

## Фотографии

Сайт показывает фотографии с Unsplash (бесплатная лицензия Unsplash). Они загружаются с CDN Unsplash в нужном размере
(адаптивные `srcset`, ленивая загрузка, главный кадр загружается первым), поэтому в проект не добавлены тяжёлые файлы.
Это иллюстрации, а не снимки реального сервиса — так и написано в подвале и в разделе «Наши работы».

Чтобы поставить свои фото, положите файлы `.jpg`, `.png` или `.webp` в `client/src/photos/` с именем-ключом из
`client/src/photos/README.txt` (например, `hero.jpg` заменит главный экран). Используйте только снимки, на которые у вас есть права.

## Что заменить, если делаете настоящий сайт

Контакты (`+380 67 000 00 00`, `example.autoservice@gmail.com`, «ул. Центральная, 15, Киев»), услуги, сроки, цены, примеры работ,
отзывы и режим работы лежат в одном файле `client/src/data/site.ts`. Там же `SITE_URL` — адрес сайта для canonical и Open Graph;
его же поменяйте в `client/index.html`, `client/public/robots.txt` и `client/public/sitemap.xml`.
Вместо схемы проезда можно встроить настоящую карту, когда будет реальный адрес. Иконки соцсетей сейчас делятся контактами
сервиса (своих аккаунтов у демо-компании нет) — замените ссылки в `client/src/components/site/Share.tsx` на свои профили.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Режим разработки: сайт на `127.0.0.1:5173` + сервер анализатора. |
| `npm run build` | Собирает сайт в `client/dist`. |
| `npm run build:pages` | Собирает сайт в `docs/` для GitHub Pages. |
| `npm start` | Запускает сервер анализатора; если сайт собран, отдаёт и его: `http://127.0.0.1:8787`. |
| `npm test` | Тесты сервера (разбор HTML, robots.txt, защита от SSRF, лимиты, оценка идей, API). |
| `npm run typecheck` | Проверка типов TypeScript для клиента и сервера. |

Данные анализатора (история, идеи, кэш) хранятся в `data/analyzer.sqlite` (создаётся сам). Удалите папку `data`, чтобы начать с чистого листа.

## Публикация на GitHub Pages (просмотр сайта по ссылке)

В папке `docs/` уже лежит **готовая статическая версия сайта** — собирать ничего не нужно.

1. Загрузите весь проект в репозиторий на GitHub (кнопка «Add file → Upload files» или `git push`).
2. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main`, папка `/docs` → Save**.
3. Через 1–2 минуты сайт откроется по ссылке `https://ВАШ-ЛОГИН.github.io/НАЗВАНИЕ-РЕПОЗИТОРИЯ/`.

Что важно знать:
- На Pages работает **сайт**. Панель анализатора там покажет «Сервер недоступен» — ей нужен сервер из этого проекта (запуск через терминал/`start.bat` работает как раньше).
- Форма записи на Pages остаётся в демо-режиме.
- Версия в `docs/` собрана упрощённым сборщиком, шрифты Manrope и Inter подключаются с Google Fonts. После своих правок пересоберите штатно: `npm run build:pages` (шрифты тогда будут встроены) и снова загрузите `docs/`.

## Публикация на другом хостинге

`npm run build` собирает статический сайт в `client/dist` — его можно выложить на любой статический хостинг. Не публикуйте панель анализатора в открытый интернет без `ADMIN_TOKEN`.

## Структура

```
client/            сайт и панель (React + TypeScript + Vite)
  src/components/  блоки сайта
  src/analyzer/    панель анализатора
  src/data/        тексты, услуги, цены, кейсы (демо)
  src/photos/      сюда кладутся настоящие фотографии
  src/styles/      дизайн-токены и стили
server/            сервер анализатора на Node.js (без внешних зависимостей)
  src/net/         загрузка страниц, robots.txt, защита от SSRF, лимиты
  src/analysis/    извлечение признаков, каталог и оценка идей
  tests/           автотесты
```

## Что проверено, а что нет

Проверено автоматически: 59 тестов сервера (в том числе «одобрение идеи не меняет файлы сайта»), проверка типов сервера, прогон интерфейса сайта и панели в браузере
на ширинах 320–1920 px (нет горизонтальной прокрутки), проверка всех ссылок и кнопок на отсутствие ошибок консоли.

Не проверено — скажите об этом честно, если покажете проект:
- В среде, где создавался проект, не было доступа к реестру npm, поэтому сборка настоящим Vite и проверка типов клиента с настоящими `@types/react` **не запускались**.
  Первый `npm install && npm run typecheck && npm run build` на вашем компьютере — это первая настоящая проверка. Если появится ошибка — пришлите текст, исправим.
- Обращения к Brave/Google/Anthropic/Telegram проверены на локальных имитациях этих API, а не на настоящих сервисах.
- Разбор HTML написан вручную (без Cheerio) и проверен на тестовых страницах, но не на большом числе настоящих сайтов.
- Анализ того, что появляется только после выполнения JavaScript в браузере, не реализован.
